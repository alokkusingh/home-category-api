# Local SLM LoRA Fine-Tuning (`training/slm`)

This module fine-tunes a local Small Language Model (**Qwen2.5-3B-Instruct-4bit** / **1.5B**) using **LoRA (`mlx-lm`)** on Apple Silicon (`arm64`) to classify Indian personal and household expenses from `Head`, `comment`, and `amount`.

---

## 1. Directory Structure

```text
home-category-api/
├── data/
│   ├── corrections.csv              # Human-verified active learning corrections (upsampled 2x)
│   └── corrections_pending.csv      # Low-confidence (< 0.55) production items awaiting review
├── model/
│   ├── expense-pipeline.joblib      # Production 3-parameter LogisticRegression pipeline (<1 ms)
│   └── expense-slm-3b/              # Fused standalone LoRA SLM weights (generated by notebook)

│   └── slm/
│       ├── README.md                # This guide
│       └── train_lora_slm.ipynb     # End-to-end Apple Silicon LoRA fine-tuning notebook
├── lora_data/                       # Auto-generated ChatML train.jsonl & valid.jsonl (gitignored)
└── adapters/                        # Intermediate LoRA adapter checkpoints (gitignored)
```

## 2. Prerequisites & Hardware Sizing

* **Hardware:** Apple Silicon Mac (`M1` / `M2` / `M3` / `M4`) running macOS.
  * **8 GB – 16 GB Unified Memory:** Set `BASE_MODEL = "mlx-community/Qwen2.5-1.5B-Instruct-4bit"` in Cell 3.
  * **24 GB+ Unified Memory:** Use `BASE_MODEL = "mlx-community/Qwen2.5-3B-Instruct-4bit"` (default).
* **Disk Space:** Ensure at least **6–8 GB free** (`df -h /`) for base model weights, checkpoints, and the fused output directory.
* **Python Kernel:** Use Python 3.10+ (`arm64` native, not Rosetta x86_64) with `mlx-lm`, `pandas`, and `scikit-learn`.

## 3. Running the LoRA Training Notebook

1. **Ensure training data is up to date:**
   * Main sheet: `~/Downloads/Expense Sheet - Categorized.csv`
   * Approved corrections: `data/corrections.csv` (promoted via `python approve_corrections.py`)
2. **Open `training/slm/train_lora_slm.ipynb`** in PyCharm or Jupyter Lab.
3. **Verify `PROJECT_ROOT` in Cell 2:**
   ```python
   PROJECT_ROOT = Path.cwd().resolve().parents[1]  # Resolves to /Users/aloksingh/git/home-category-api
   ```
4. **Run all cells sequentially:**
   * **Cell 1:** Installs `mlx-lm`, `pandas`, and `scikit-learn`.
   * **Cell 2:** Cleans UPI/SBI SMS boilerplate, preserves English + Hindi/Devanagari (`ऑटो`), normalizes diagnostic/blood tests to `Medical`, upsamples `data/corrections.csv` (`2x`), and writes stratified `lora_data/train.jsonl` and `lora_data/valid.jsonl`.
   * **Cell 3:** Runs 500 iterations of LoRA fine-tuning on Apple Metal GPU (`adapters/expense-lora`).
   * **Cell 4:** Evaluates exact holdout accuracy, F1-score, and checks for out-of-vocabulary category hallucinations.
   * **Cell 5:** Runs edge-case regression checks (`Dishwasher` amount sensitivity, `Hotter recho` + `JioHotstar`, Hindi `ऑटो`, `Detergent powder`, etc.).
   * **Cell 6:** Fuses the LoRA adapter into a standalone model at `model/expense-slm-3b`.

## 4. Classical ML vs. LoRA SLM (When to Use Each)

| Feature | Classical Pipeline (`train_model.py`) | Local LoRA SLM (`train_lora_slm.ipynb`) |
| :--- | :--- | :--- |
| **Algorithm** | `TF-IDF (Word + Char N-Grams) + LogisticRegression` | `Qwen2.5-3B-Instruct-4bit + LoRA` (`mlx-lm`) |
| **Inference Latency** | **~0.5 ms / row** (~50 ms for full Google Sheet) | **~30–80 ms / row** (~2–3 min for full Google Sheet) |
| **Runtime Footprint** | ~80 MB RAM, runs on any Linux/Docker CPU | ~2–4 GB Unified Memory / VRAM (Apple Metal or GGUF) |
| **Training Time** | **~2 seconds** | **~5–10 minutes** on Apple Silicon GPU |
| **Best Role** | **Primary Production Engine** (fast, deterministic, calibrated probabilities) | **Experimentation & Tier-2 Fallback** for unseen Indian merchants/brands |
